# Implementation Plan: The curriculum ladder

**Branch**: `046-curriculum-ladder` | **Date**: 2026-07-25 | **Spec**: [spec.md](./spec.md)

## Summary

The ladder rides four shipped seams and reserves two contracts. (1) **Stage fact**:
an immutable additive `Stage` (+ `StageOverridden`, `CharterPreset`) on the
`world.json` Manifest, validated at open, absent = ungated pre-ladder world.
(2) **Gating**: a stage→ceiling table intersected into the grant set at the two
manifest-load sites (the bundle-narrowing precedent), before roster derivation — so
declaration, prose, and door gating inherit the stage with no new layers; stage-1
additionally serves its charter preset constant as the effective charter (edits get
the shipped notice treatment, never silence). (3) **Unlocks**: a per-user
`~/.promptworld/unlocks.json` under the worlds-registry doctrine (advisory, load-
tolerant, atomic writes, evidence pointers into the proving world); creation UX =
`promptworld stages` + informed `--stage`/`--override`. (4) **Announcement**: new
executor-class `curriculum.exercise_passed` / `curriculum.stage_unlocked` events with
full catalog/digest/chronicle wiring — emitted in production by TASK-119's rubric
machinery later; proven now by fixture emission. Exercises ship as content contracts
shaped for 119's config block; stage display identities live in an `internal/skin`
stub TASK-121 absorbs. Decision log: [research.md](./research.md) R1–R12.

same-seed cross-stage determinism diff; fixture-driven unlock chain; TestCatalogSweep;
player-docs freshness script for the four quickstart pages

**Project Type**: single Go project — `internal/world`, `internal/metatron`,

(tutor preset), `internal/skin` (new stub), `internal/mind` (chronicle line),

load, already fresh-read); unlocks file touched only on pass events and CLI reads

property preserved); unlocks record advisory-never-authority; all machinery
model-free (FR-014); additive omitempty everywhere (snapshot/manifest byte-compat)

**Scale/Scope**: 4 stages, 2 exercise definitions, 2 new event types, 1 new user-scope
