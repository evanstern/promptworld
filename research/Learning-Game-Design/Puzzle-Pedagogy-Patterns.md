# Puzzle Pedagogy Patterns

How the Zachtronics family (TIS-100, SHENZHEN I/O, EXAPUNKS, Opus Magnum) and adjacent
games teach programming-shaped skills through play. Four recurring patterns show up in
the corpus ([[_grounding]] § Area 1).

## 1. The manual is a game artifact, not paratext

TIS-100's 14-page technical manual is "the game's primary teaching tool" — there is no
tutorial; players print and consult the manual. Zach Barth's own framing: "having a
tutorial that basically says 'Hey, read this 14-page manual, asshole,' seems like it would
be a really bad thing for your game, but apparently it's actually pretty effective"
([Game Developer](https://www.gamedeveloper.com/design/-things-we-create-tell-people-who-we-are-designing-zachtronics-i-tis-100-i-)).
The document also carries the fiction: "The manual has references which imply things about
the world" ([[_grounding]]). SHENZHEN I/O extends this to datasheets and application notes;
EXAPUNKS re-skins it as a hacker zine, TRASH WORLD NEWS, through which "players learn to
program" ([Zachtronics Museum](https://www.zachtronics.com/zachtronics-museum/)).

## 2. Open-ended solution spaces instead of single answers

Zachtronics builds "a certain minimum set of tools that create emergent properties when
used together" and reports that "as long as the toolset is expressive and the problem is
open-ended, we will see creative solutions from players, including optimizations we hadn't
really dreamed of before" ([Road to the IGF interview](https://www.gamedeveloper.com/business/road-to-the-igf-zachtronics-i-opus-magnum-i-),
[[_grounding]]).

## 3. Histogram feedback and social comparison, without rewards

Opus Magnum scores each solved puzzle on cost, cycles, and area, shown "both on a histogram
and listed against your Steam friends." Optimization is motivated by comparison ("You
finish a puzzle and see your friend completed it in fewer cycles…") and by shareable GIF
exports — while the studio "deliberately [doesn't] offer any kind of in-game rewards for
optimization, so the players who do are often more intrinsically motivated"
([[_grounding]] § Opus Magnum).

## 4. Deliberately narrow audience; education as a stated aim

TIS-100 "almost pushes you away… it's not designed to be this widely-accessible game that
anyone can play" ([[_grounding]]). The studio's Zachademics program gives all its games
free to public schools, describing them as teaching "assembly code, registers, and
parallel programming" and reinforcing "iterative problem solving and the design feedback
loop" ([Zachademics](https://www.zachtronics.com/zachademics/)).

## Adjacent evidence

- Human Resource Machine has been analyzed against Papert's constructionism as teaching
  code concepts through "story, graphics, and sequential problem-solving" ([[_grounding]]).
- Practitioner essays describe Factorio as implicit software-engineering pedagogy —
  refactoring ("You build something small that works, iterate on it, and refactor"),
  bottleneck monitoring, trade-off decisions — though these are engineer blog essays, not
  studies ([[_grounding]] § Adjacent).
