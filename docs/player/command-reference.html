Command reference

Every command the promptworld program accepts, grouped by what you're trying to do. For a guided first run instead of a lookup table, see getting started.

The one rule every command shares

Almost every command below takes a world as its first argument — either the world's name (if you created it the normal way) or a path to its folder directly. Anything containing a /, or starting with . or ~, is treated as a path; anything else is treated as a name. A bare name is looked up first among the worlds you've created the normal way, then among any worlds you registered elsewhere with new --at — an unknown name fails with a clear error, and a name that matches two different worlds refuses rather than guessing.

By default your worlds — and this lookup list — live under ~/.promptworld. Setting the environment variable PROMPTWORLD_HOME moves that whole home elsewhere, and every command below honors it.

Making a world

new <name>

Creates a brand-new world. Give it a plain name and it's created in your default worlds folder; give it a path instead and it's created exactly there. Either way you get a fresh village, seeded with its eight starting villagers and a guardian charter ready to read.

FlagWhat it does
--at DIRCreate the world at a specific folder instead of the default worlds folder, and remember it under its name for later
--seedPick a specific starting seed instead of a random one
--teachingMark this as a teaching world — the game will default it to the fastest speed your machine can safely think at, every time it starts
--stage stage-1..stage-4Choose which curriculum stage to start at (defaults to the highest stage you've already earned)
--overrideStart at a stage you haven't earned yet — the game records this honestly rather than pretending you earned it
--charter-preset default|tutorChoose the starting guardian instructions; a fresh stage-1 world uses the friendlier tutor preset unless you opt out
--scenario <exercise-id>Start inside one of the game's structured teaching exercises instead of an open-ended village

migrate <world>

Upgrades an older world's save files to the current version, so a world you haven't opened in a while keeps working. No flags — point it at the world and it does the whole upgrade in one run, keeping an archived copy of the old save alongside the new one.

stages [--json]

Shows all four curriculum stages — what each one teaches, what it lets your guardian do, and what earns the next one — plus which ones you've already earned. Always shows all four, never just the ones you've unlocked. --json prints the same information in a machine-readable form.

Running it

start <world>

Starts a world running in the background, so it keeps going after you close the terminal. This is the one most players want.

daemon <world>

Runs a world in the foreground, right in this terminal window — useful when you want to watch its own output directly, or want it to stop the moment you close the window. No flags.

stop <world>

Stops a running world cleanly. Safe to run even if the world isn't running — it just says so and does nothing.

status <world> [--json]

Prints a world's current state: what tick and game time it's at, whether it's paused, your AI providers' health, whether they're calibrated, and any warnings that need your attention. Works even when the world isn't running, by reconstructing its last known state from the save. --json prints the same facts machine-readably.

ps [--all] [--json]

Lists every world promptworld knows about on this machine, and — this is the useful part — whether each one is really running: a world only counts as running if it actually answers when asked, not just because its process looks alive. By default only running/paused worlds show; --all adds stopped ones too. --json prints the same table machine-readably.

Watching it

ui <world>

Opens the full interactive on-screen view for a running world — the map, the story feed, the guardian conversation, and your villagers, all at once. See what do all those things on screen mean and the keys reference for how to use it. No flags.

attach <world>

A simpler, line-by-line live view from any terminal: a status header, a stream of events as they happen, and typed commands (pause, resume, speed <v>, status, quit). Quitting just detaches — the world keeps running. No flags.

tail <world> [--since SEQ] [--follow]

Prints recent history from a world's save — the last 20 entries by default — and works even when the world isn't currently running. --since SEQ only shows entries after a given position; --follow keeps streaming new entries live (this needs the world actually running).

Playing it

guardian <world> [message...]

Talk to your world's guardian — the voice you play through. Send it a message for one mediated turn, and it prints what happened: any surfaced moments, its reply, any vision or omen that landed, and your remaining charges. Run it with no message instead for a quick status peek: your charges, where your charter came from, and any standing orders you've placed.

work <world> <snap-time|give|move|remove> ...

The direct, no-conversation door to the guardian's own workings — for when you want to act immediately rather than ask: jump time (snap-time <day> <HH:MM>), give a villager an item (give <villager> <item> <qty>), move something (move <class> <x,y> <x1,y1>), or remove a structure, pile, or terrain tile (remove <class> <x,y> — villagers can't be removed this way).

FlagWhat it does
--forceSkip the normal charge cost for this one working

pause <world> / resume <world>

Pause or resume a running world's clock. No flags.

speed <world> <value>

Changes how fast time passes in a running world, printing the resulting clock line. If your AI can't keep up at the speed you ask for, you'll see a warning right after — see troubleshooting for what that means and what to do about it.

teaching <world> [on|off]

With no argument, reports whether a world is currently marked as a teaching world. With on or off, changes the marker — the change applies the next time the world starts, not while it's already running.

The AI

See also the AI behind the village and AI setup basics for what these commands are talking to.

llm <world> <kind> <prompt...>

Sends a one-off message straight to one of your configured models yourself, bypassing the guardian entirely — useful for checking your setup actually works. Prints which provider answered, the model, tokens, cost, and how long it took.

FlagWhat it does
--systemAdd an extra system-level instruction to the call
--max-tokensCap how long the reply is allowed to be

calibrate <world> [--provider <name>] [--samples N]

Benchmarks your configured AI providers on your own hardware, so the game knows how fast they really are and which speeds it can safely think at. Writes what it learns to this world's save so future runs remember it, and prints the fastest speed each kind of thinking can run at ("planner suppressed above 16x", for example).

FlagWhat it does
--provider <name>Only benchmark one named provider instead of every configured one
--samples NHow many timing samples to take (default 5)
--tier local|cloud|allAn older way to pick which providers to benchmark — still works, but is a deprecated stand-in for --provider

divergence <world> [--json]

Prints recorded evidence for how much a newer, relevance-aware way of picking which memories matter would have changed what your villagers recalled, compared to today's behavior. Read-only evidence for a decision — running this command never changes anything by itself. --json prints the same rows machine-readably.

Comparing runs

fork <world> <new-name>

Copies a stopped world, at its latest save point, into a brand-new world under a fresh name — the original is left completely untouched. The two worlds share the same history up to the copy, then run forward independently, so trying a different charter (or anything else) on the fork is a controlled experiment against the original.

FlagWhat it does
--at latest-snapshotThe point the copy is taken from — today this is also the only value accepted, so it's already the default

compare <a> <b> [--since TICK]

Compares two worlds side by side — the natural next step right after fork, to see how the copy and the original turned out differently. Works whether either world is running or stopped. --since TICK narrows the comparison to only what happened after a given point instead of the whole shared history.

Two names you might see in old scripts

metatron and miracle were promptworld's original names for what are now called guardian and work. They still work exactly the same as their current names — nothing about them was removed — but they no longer appear in the program's own built-in help text, so if you're starting fresh, use guardian and work instead. If you run across one of the old names in an older script or note, now you know what it means.
