Getting started

From "never seen this before" to a village running in your terminal — install, create a world, start it, and watch it live.

What promptworld is

promptworld is a terminal game on a procedurally generated map. You don't play a character — you populate a small village (8 villagers) and watch it run. Each villager has its own mind: some decisions come from a language model "thinking" for them, and simple things (walking, sleeping, eating) happen on the spot without any model call. The village is ambient and always-on: once you start a world, a background process (the "daemon") keeps simulating it around the clock, whether or not you're watching. You attach and detach like tuning into a channel — the world doesn't pause just because you looked away.

Set your expectations now: your first village will probably see someone freeze or starve. That's the story working, not a bug. promptworld doesn't soften failure — a villager who dies stays dead, permanently, with no reload and no undo. Even the gru, the night predator that stalks the village after dark, plays by honest rules: a healthy villager always survives its attack, but one already badly worn down — no fire, no food, wounds untreated — can now be killed outright. A death always traces back to neglect that could have been prevented, never to one unlucky roll. That's exactly what makes the village's chronicle worth reading: it narrates a death the same as anything else that happened, and the postmortem — what led up to it, who was there, what changed after — is the payoff, not a punishment for playing wrong. Losing a villager, or even a whole village, is part of what you came here to watch.

And that goes all the way up: when your last villager dies, the run itself is over. If you're watching in the full-screen client, a summary of the whole run takes over the screen right then — how it ended, and (on a scenario world) whether you passed. The world stops — but it never disappears. It stays on disk as a readable archive: the narrated story, the raw event feed, and the morgue, a file holding a factual epitaph for everyone who died (the reading the story page covers all three). An ended world opens read-only — you can look at everything, you just can't run the clock again. Playing again means creating a new world; the old one keeps its story forever.

Before you start

You need Go installed to build the program. You do not need any AI model configured to get a world running — without one, villagers still walk around and handle their basic needs, just without model-driven decisions ("reflex-only" minds). If you do want AI-driven villagers, you'll want a local model server (an OpenAI-compatible endpoint, e.g. Ollama running at its default address) with gemma4:latest pulled — that's the model a fresh world expects out of the box, chosen because it reliably follows the game's instructions rather than needing extra tuning — and optionally an ANTHROPIC_API_KEY for the higher-quality cloud-narrated story feature. The AI setup basics page covers the minimum you need to flip that on; you can always come back to it.

1. Build the binary

go build ./cmd/promptworld

Everything — running the world, watching it, and managing it — is one program: promptworld.

2. Create a world

promptworld new demo --seed 42

This creates a new world named demo. A world is a self-contained save directory (by default under ~/.promptworld/worlds/demo) holding everything about that run — the map, the villagers, the history, and its AI configuration file. The --seed is a starting number for the world's random generation; the same seed always regenerates the identical map and starting conditions, so it's worth writing down if you want to recreate a world later. Leave it off and promptworld picks one for you.

Add --teaching if you want a teaching world — one that always starts at the fastest speed its measured setup can honestly keep villagers genuinely thinking at, rather than the ordinary default speed (you can also flip this on or off later with promptworld teaching demo on / off). The time & speed page covers what that means in practice.

Every world is also created at a stage — promptworld has four named ones (The Voice, The Written Word, The Craft, The Stewardship), and each is an identity that decides what your guardian angel can do in that world and what you're learning by playing it — and in the early stages the screen itself pitches in: the first time something new happens (a gru attack, an expired order, a skipped thought), a two-line lesson tip appears above the message box, once ever, pointing at the key that shows you more. A new player starts at the first, The Voice — that happens automatically, no flag needed. Run promptworld stages any time to see all four laid out, with what each one teaches and what unlocks the next. You're never fenced in: you can skip ahead to a later stage with an explicit override, and promptworld will tell you plainly what you'd be skipping before it does. Every stage ships seeded practice exercises you can run directly with --scenario <exercise> — nine in all, two or three per stage, each a world built to test one specific thing, with its own tab on screen tracking how you're doing (see the stage pages). At the first stage the guardian also has a built-in tutor's habit: it explains the game as you go and always pulls its exact numbers (prices, costs, the charge economy) from the game's own facts rather than guessing — ask it anything, including "what does that cost?"

Genesis also writes each villager's starting personality and the guardian's starting "charter" — more on both in a moment. The summary printed when the world is created also names the AI model it's expecting and the exact command to fetch it if you haven't already (local model: gemma4:latest — pull it first if you haven't: ollama pull gemma4:latest) — that line always matches what was actually written, so there's never a mismatch between what the world wants and what it tells you to install.

3. Start it

promptworld start demo

This starts the world's daemon in the background (detached — it survives you closing the terminal) and confirms it's up before handing control back to you. From this moment the world is running 24/7, ticking away even if you don't attach to it again until tomorrow. If something goes wrong, promptworld will point you at daemon.log inside the world's save directory.

If your world has AI-driven villagers and you haven't run promptworld calibrate on it yet, the very first start prints a loud, one-time warning: the world has never been benchmarked against your actual computer, so it's making cautious built-in guesses about how long AI thinking takes instead of a measured one. The warning names which kinds of villager thinking — planning, conversations, meetings — would get paused at which speeds under those cautious guesses, and gives you the exact command to fix it, e.g. promptworld calibrate demo. Nothing is broken and nothing is blocked while you're uncalibrated; the world runs fine either way, calibrating just makes its speed decisions match your actual setup instead of a worst-case guess. A teaching world (see step 2) leans on this even more directly: it can't honestly pick its fastest-safe default speed until it's calibrated, so an uncalibrated teaching world asks you to run promptworld calibrate demo before it can show you a real number instead of a cautious guess.

You can check on any world, running or not, from anywhere:

promptworld ps        # every running world you have, at a glance
promptworld status demo   # this world's tick, game time, and speed

If you did set up a local AI model and it's missing, unreachable, or answering but never actually cooperating with the game's instructions, promptworld notices on its own and says so loudly — a WARNING line right in status, naming the problem and what to do about it. It clears itself the moment the problem is fixed, with no restart needed. status also lists, per configured AI provider, whether it's been calibrated — the date you last ran calibrate, or uncalibrated (bootstrap) if you haven't yet.

status also prints one horizon: line per kind of villager thinking — planning, conversations, meetings — telling you live whether it's currently keeping up (thinking at <speed>) or being suppressed to keep the world running smoothly (suppressed at <speed> — calibrate or slow down), with a running skipped N count of how many thoughts that class has lost since the daemon started. It's the same information as the one-time calibration warning above, just live and ongoing instead of a single boot-time notice.

4. Watch it live

Two ways to watch, both non-destructive — quitting either one just detaches; the world keeps running underneath.

  • promptworld attach demo — a simple line-by-line feed of events as they happen, plus typed commands (pause, resume, speed <v>, status, quit).
  • promptworld ui demo — the full-screen visual client: a one-line roster strip right under the header (a count plus one letter per villager, for a glance at everyone without opening a tab), a map of the village on one side, and a tabbed panel on the other for the chronicle (the narrated story so far), the guardian (your conversation with the village's watcher, previously called Metatron — see the next page — whose pane also lists any standing orders you've placed with it), the villagers themselves (their needs, goals, and inventories), and a systems tab holding the technical dashboards (every configured AI model, how busy it is, and what it's cost you) — plus, on a world created with --scenario, a fifth tab tracking that exercise's progress. As your village grows, the map itself grows with it — any walls or paths villagers have built show up as their own distinct glyphs alongside fires, shelters, and stockpiles. One line above the message box you type to the guardian in always shows your charge bank, when the next charge arrives, and how many standing orders are running, no matter which tab is open. Press G (capital) at any moment to open the guardian console — a full-screen page for that same conversation, laid out as a readable document with your charter and skill files shown alongside it. This is the recommended way to actually play.

Inside the full-screen client, ? opens a built-in help overlay at any moment — the keys for the screen you're on plus a tour of everything visible — so you never have to leave the game to look something up. Beyond that, see the screen-orientation page for a full tour of what's on screen — the header, every map glyph, the story feed, and the tabbed panel — and the keys reference card for every key the full-screen client responds to.

As a village develops, the map itself can grow busier: villagers may raise walls (wood-plank or stone) to mark off or block access to an area, and lay paths that let anyone crossing them walk noticeably faster. Both simply show up on the map as they're built.

In the full-screen client, space bar toggles pause/resume, and bracket keys ([ / ]) step you through the speed ladder. The header always shows the world's current speed, and — if you've configured AI-driven villagers and asked for a speed the world can't quite keep sensible thoughts up with — a short note like asked 32x — 3 minds in flight, debt 140%, meaning the world has quietly dropped a notch on its own for now. The time & speed page explains what those numbers mean and why that happens. That same header also grows a red [llm: ...] badge if your AI model runs into trouble — the same condition status warns about, just visible at a glance while you're watching — and, whenever any kind of villager thinking is currently being suppressed for speed, a [suppressed: ...] badge naming which kinds. The full-screen client's systems tab goes further, listing each kind of thinking with its own live status and skipped-thought count.

5. Ask your guardian one thing

Everything so far has been setup and watching. Now type something. Open the guardian tab in promptworld ui (or press G for the full-screen console) and put one concrete ask into the message box:

"show Ash a vision of the fire dying"

That's a private word to one villager — a vision, one of the handful of things your guardian can do at the first stage (alongside an omen, a message the whole village hears, and a watch, which asks it to keep an eye out and act the moment something happens). Send it and see what comes back: the guardian replies or acts on it, and the line above the message box — the one tracking your charge bank — is where the cost of that ask shows up. This works on any world, right away: no --scenario, nothing to set up first.

That sample line is one phrasing from the default Guardian skin — the fiction this game ships with out of the box. Your own world might be running a different skin with its own voice, so don't take the words above as universal: press ? for the built-in help overlay, and its guardian section lists one example ask per verb your world actually grants, in your world's own phrasing. That live, per-world list is always the one to trust for "what can I say."

6. When you're done for now

Quitting attach or ui only detaches your view — the daemon keeps the village running. If you actually want the world to stop simulating (e.g. you're shutting down your machine), stop the daemon itself:

promptworld stop demo

This is a graceful stop — it finishes its current bookkeeping before exiting. The world resumes exactly where it left off next time you start it, even if it was killed abruptly instead. stop and status both work even on a world made by an older version of promptworld that you haven't upgraded yet — you don't need to run migrate first just to check on it or shut it down.

7. Try a change on a copy (fork & compare)

Once a world has run for a while, you can copy it and experiment on the copy. promptworld fork demo demo-b makes a new world, demo-b, that is the same village with the same history up to its latest save point — same people, same map, same story so far — under its own name. Edit the copy's guardian instructions, start both worlds (they run side by side), and later run promptworld compare demo demo-b to see, plainly, what your change did: a scorecard for each world and the point where the two stories started to differ. Forking only works while the source world is stopped, and the two worlds stay separate forever — there is no way to merge them back together.

Quick reference

go build ./cmd/promptworld

promptworld new demo --seed 42     # create a world
promptworld start demo             # start the daemon (detached, runs 24/7)
promptworld ps                     # see every world you have running
promptworld status demo            # tick, game time, speed for one world
promptworld attach demo            # watch live, line-mode; quit just detaches
promptworld ui demo                # full-screen map + chronicle + guardian + villagers
promptworld stop demo              # graceful stop; resumes cleanly next start
promptworld fork demo demo-b       # copy a stopped world to experiment on
promptworld compare demo demo-b    # scorecards + where the two stories split
promptworld help                   # the full command list
