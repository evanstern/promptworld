Troubleshooting

Seven things that actually go wrong, in your own words — what's probably happening, what to check, and what to do about it.

"I tried to start my world and it refused."

What's probably happening: either a copy of this world is already running somewhere, or its save has a problem serious enough that the game won't risk running past it.

What to check: run promptworld ps (see the command reference) to see if this world is already listed as running. If it isn't, look in the world's own folder for a file called daemon.log — that's exactly where a background start's own output goes, and it will say plainly what refused.

What to do: if the world is already running elsewhere, connect to that instead of starting a second copy — promptworld ui, attach, or status all work against an already-running world. If daemon.log instead points at a problem with the save itself, that's real damage to the save's history, not something the game can repair on its own — your only way forward is an earlier backup of the world's folder, if you kept one.

"The world shows as running, but nothing responds."

What's probably happening: the world's background process is still alive, but it's stopped actually answering — wedged rather than working.

What to check: promptworld ps reports this state honestly rather than trusting the process alone: a world only shows as running or paused if it actually answers a status check; a process that's alive but silent shows as unresponsive instead.

What to do: an unresponsive world isn't usable as-is. Stop it — promptworld stop will fall back to forcing it closed if it can't reach it politely — and start it again.

"My villagers only do basic survival things and never seem to think."

What's probably happening: either no AI model is configured for this world at all, so it's running on reflexes alone by design, or one is configured but isn't actually working right now, or your world's current speed is asking your configured model to think faster than it can. See the next two entries for how to tell which.

"No model is configured — or one is, but it isn't working."

What to check: first, does this world's folder have an llm.json file at all? If it's missing (or you deleted it), the game is running entirely on reflexes by design — there's no AI thinking to check on. If llm.json exists, look for a daemon: WARNING llm provider "<name>": ... line in the daemon's log, or — if you're in the on-screen view — a red [llm: ...] badge in the header along with a detail line under that provider in the systems tab. Both name the exact problem and a remedy.

What to do: if there's no llm.json, see AI setup basics and the world files reference to add one. If a warning names a specific provider, its own remedy text tells you what to fix — commonly, the model your llm.json names isn't actually being served at that provider's address (check it's really running there), or the endpoint itself isn't reachable, or the model answers but never uses tools (in which case switching that provider to the JSON tool-calling mode, or trying a different model, is the fix).

"My AI is configured, but it seems too slow for how fast I've set the world."

What to check: in the on-screen view, look for a [suppressed: ...] badge in the header, or a horizon line in the guardian pane — both mean some kind of thinking (planning, conversation, or meetings) is being skipped at your current speed because your model can't keep up with it.

What to do: the game measures "how fast can my model think" through promptworld calibrate (see the command reference) — running it gives the game an accurate, hardware-proven measurement instead of a cautious guess, which can raise the speed a given kind of thinking can survive at. If it's still too slow even calibrated, the honest fix is to run the world at a lower promptworld speed instead.

"The game says my save is too old (or too new) and won't open."

What's probably happening: this world's save was written by an older (or newer) version of promptworld than the one you're running now, and the format has changed since.

What to check: promptworld ps will still list a world like this rather than pretending it doesn't exist — it just can't be opened normally. Commands that only need to reach an already-running daemon, like stop and status, work on a version-mismatched world even though opening its save directly doesn't — so you're never stuck unable to even check on or stop one.

What to do: if your save is older than what this build understands, promptworld migrate <world> is the one-time upgrade — point it at the world and it brings the save up to the current format, keeping an archived copy of the original alongside it. If instead your save is newer than what this build understands, migrating can't help — that direction means your own copy of promptworld needs upgrading.

"The world is running, but nothing new is showing up in the feed."

What's probably happening: most often, the world is simply paused — a paused world has nothing new to report, so its feed sits still, which looks alarming but is completely normal. Less commonly, the on-screen view's connection to the world has dropped and hasn't caught back up yet.

What to check: run promptworld ps and look at the STATE column for this world — it distinguishes paused from running plainly.

What to do: if it says paused, resume it (the space bar in the on-screen view, or promptworld resume) and the feed picks back up immediately. If it says running and the feed is still stuck, close and reopen your viewer — it reconnects and catches back up on its own.
