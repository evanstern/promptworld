World files reference

Every world you create lives in its own folder — one folder, one world, nothing shared between them. Here's what's in it, and for each file, whether it's yours to edit.

Every entry below carries one of three labels:

  • yours to edit — this is how you influence the game; edit it freely
  • read it, don't edit it — useful to look at, but the game writes it for itself and your edits won't stick, or won't mean what you'd expect
  • leave it alone — internal machine state; editing it by hand can corrupt your world

charter.md — yours to edit

Your guardian's standing instructions — the closest thing this game has to "how I want to play." The guardian re-reads this file fresh on every single turn, so an edit takes effect immediately, on your very next message. If the file goes missing, it's quietly restored to its starting text. If you edit it while playing at the very first curriculum stage, the game tells you plainly that written instructions don't bind yet at that stage — it still runs your starting charter until you reach the stage where authored instructions unlock.

llm.json — yours to edit

Which AI models your guardian and villagers think with, and how spending against them is capped. This is the one file every player eventually touches — a fresh world is written with a working local-model default, but you'll edit this to add your own providers, change the monthly budget, or point a call kind at a different model. Editing it takes effect the next time the world's daemon starts (stop it, edit, start it again). Deleting it entirely is legal too — the game just runs on reflexes alone, with no AI thinking at all.

The full field-by-field reference — every provider setting, the routing rules, and the money/budget rules — lives in the AI providers guide; this page only tells you it exists and that it's yours to edit. See also AI setup basics for the minimum you need to get started.

skin.json — yours to edit

An optional file that lets you re-voice how the guardian and the curriculum stages are named and described on screen — a purely cosmetic override. If the file is absent, the game's own default identity ("Guardian" and the four default stage names) is used; nothing about the game's rules or mechanics ever changes based on this file, only the words you see. Like llm.json, an edit takes effect the next time the world's daemon starts.

tuning.json — yours to edit (advanced, optional)

An optional file that moves a small, named set of the game's numeric doctrine — things like how quickly a fire needs refueling, or how often a gru might emerge at night — from a fixed setting onto a per-world dial you can adjust. It's sparse: you only need to set the dials you actually want to move, and an absent file behaves exactly like the game's original, unmoved defaults. Values outside the accepted range are automatically pulled back to the nearest allowed bound, with a warning; a genuinely malformed file refuses to start rather than silently doing something you didn't ask for. This is an advanced file — most players will never need it, and every dial it can move already has a sensible default.

calibration.json — leave it alone

The recorded results of benchmarking your AI providers — how many seconds each one takes per unit of thinking, on your own hardware. This file is written only by the promptworld calibrate command (see the command reference); the running game itself never writes to it. If it's missing or unreadable, the game just falls back to cautious built-in defaults rather than failing — so there's never a need to hand-edit this file yourself; run calibrate again instead if the numbers need refreshing.

village_charter.md — read it, don't edit it

Not to be confused with your own charter.md above — this is the village's own self-legislated law, written entirely by the villagers themselves through their daily meetings and votes, and rewritten by the game every time a rule is proposed, amended, repealed, or a villager is exiled. It's a great read for catching up on what your village has decided for itself, but there's no mechanism for you to edit it — the game regenerates it from the recorded history of your village's own governance.

The world manifest (world.json) — leave it alone

The file that identifies your world: its name, its random seed, its map size, and a handful of settings fixed permanently at the moment you created it (like which curriculum stage it started at). Most of what's in here is meant to be set once, at creation, by promptworld new's own flags — not hand-edited afterward. A couple of fields do change over the world's life, but always through their own dedicated command rather than a text edit — for example, promptworld teaching <world> on|off is how you flip the teaching marker, not editing this file directly.

The event log and snapshots (world.db) — leave it alone

The actual history of your world — every single thing that has ever happened in it, recorded permanently and in order, plus periodic saved snapshots of the full state so the game doesn't have to replay that entire history from scratch every time it starts. This is the closest thing your world has to its soul; there's no supported way to hand-edit it, and doing so risks corrupting your save beyond repair. If you want a backup of a world, the whole folder — this file included — is what you'd want to keep safe.

bundles/ — yours to edit

An optional folder where you can drop in extra tools for your guardian to use — small, self-contained packages that add new things it can do, beyond what the game ships with out of the box. An empty or absent bundles/ folder changes nothing; a badly-formed bundle inside it is skipped with a note in the daemon's log rather than stopping your world from starting. Authoring your own bundle — the file format, the available building blocks, worked examples — is documented separately in the bundle authoring guide; this page only tells you the folder exists and it's yours to add to. Changes here take effect the next time the world's daemon starts (bundles load once, at boot).
