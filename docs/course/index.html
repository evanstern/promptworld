A Village That Runs Itself

Picture a lighthouse keeper's logbook. Nothing officially happened at the lighthouse unless it was written down — and every entry says exactly where, when, and why. promptworld runs on that same idea, except the lighthouse is a tiny village and the keeper never sleeps.

⏱️

02

The Clockwork Heart

Why replay never lies

Kill it. Restart it. Nothing changes.

Picture a player piano. The paper roll has holes punched in it, and any piano that loads that roll plays back the identical performance — same notes, same timing, forever. The pianist who punched the roll doesn't need to be in the room anymore.

You can stop the promptworld daemon mid-tick, delete every scrap of its running memory, and restart it cold. The village comes back byte-for-byte identical, every villager in the exact spot, every memory intact.

How is that possible? This module is the answer — and it's the same trick behind one of the most valuable patterns you can ask an AI coding assistant to build for you.

The one law

The sim runs on a single rule: state only ever changes by applying recorded events, in order. Three mechanisms make that rule unbreakable.

📜

The append-only ledger

Every world is a SQLite file with an append-only event log. Deleting a row is impossible by design — a database trigger forbids it, and every sequence number is checked for gaps.

⚙️

The reducer

One function — the reducer — is the ONLY way state changes. The exact same function runs live and during replay: load the newest verified snapshot, then re-apply.

🎲

Deterministic dice

Even randomness is deterministic: every random draw comes from the world's seed, a purpose, and the current tick. Replay rolls the exact same dice.

💡
Key insight

This is event sourcing — one of the most powerful patterns you can ask an AI assistant for. If your own app's data ever gets corrupted, or you've wished you could rewind and see exactly what happened, this is the pattern to name.

Two doors, and nothing else

The AI mind — the part that decides what a villager wants — runs entirely outside this clockwork. Its output can only enter as a recorded event, and only through two guarded doors.

Giving Memories Coordinates

How the village turns raw text into numbers a computer can compare — and why those numbers get recorded once, never recomputed.

A Star Chart for Memories

How would a computer know that "my spear broke at the river" and "I lost my axe by the water" are about the same kind of trouble? Not a single word matches between them.

promptworld solves this by giving every memory a set of sky coordinates. An embedding model reads a memory's exact text and returns a vector — 384 numbers, positioned so that similar meanings land near each other, like stars in the same constellation.

"My spear broke at the river"
"I lost my axe by the water"
"The current swept away my net"
"The harvest festival was joyous"
"We danced until sunset at the festival"
"A stranger asked about the road"
"My hut leaks when it rains"
"Wolves howled near the fence"

This is a 2D cartoon of 384 dimensions — the real map has far more axes than a page can draw.

Similarity stops being a guess about matching words and becomes cosine similarity — a distance you can actually measure.

The Clock Never Waits for the Embedder

Step 2 of that animation is one small function. When a fresh batch of events arrives, the embedder either catches it immediately or lets it go — no waiting, no blocking, ever.

CODE 

func (e *Embedder) Observe(events []store.Event) {
	select {
	case e.events <- events:
	default:
	}
}
PLAIN ENGLISH

This is Observe — the mail slot the embedder listens at for freshly logged events.

Try the following, but never sit around waiting for it to succeed.

If there is room, drop the new events onto the embedder's own channel.

If there is no room — the embedder is still busy with the last batch — do nothing and move on.

End of the try-or-drop check.

End of Observe. The clockwork never had to pause for the embedder to catch up.

Think of it as a mail slot that holds exactly one envelope. If the embedder has not picked up the last delivery, a new one just bounces off the door — nothing jams, nothing waits.

The Envelope the Embedder Mails Back

Once all-minilm returns its 384 numbers, the embedder wraps them in a struct and mails it through the social door as an agent.memory_embedded event.

CODE 

	MemoryEmbeddedPayload struct {
		Agent   int       `json:"agent"`
		MemSeq  int64     `json:"mem_seq"`
		Vec     []float32 `json:"vec"`
		Model   string    `json:"model"`
	}
PLAIN ENGLISH

The shape of the envelope itself — MemoryEmbeddedPayload, written as a JSON payload.

Agent: whose memory this is, by villager ID.

MemSeq: which memory, by its position number in that villager's own log.

Vec: the actual coordinates — the 384 numbers describing what the memory means.

Model: the name of the model that produced these numbers, recorded right alongside them.

That is the whole envelope. Four labeled fields, nothing hidden.

Notice what's missing: no timestamp saying "embed this now." The reducer is the only thing allowed to attach this vector to a memory's permanent record, and it always does so after the memory already exists — so having no vector yet is a perfectly legal, temporary state.

Three Things Worth Knowing

📢
Failure is loud, never a stall

If the embedding model or its local endpoint goes down, memories keep happening — they just stay vectorless. The operator sees exactly one warning, never a crash or a frozen village.

🗺️
Different model, different chart

Every vector is stamped with the model that produced it. Numbers from two different models are like coordinates from two different star charts — comparing them is meaningless, so the system refuses to.

🔥
Kept warm on purpose

all-minilm is tiny (about 46 MB) and gets pinned in memory at startup, so there is no cold start lag. The big chat models are deliberately left unpinned.

🔥
The One Line That Keeps It Warm

Deep in internal/llm/providers.go, this single line is the reason there is no cold-start lag:

body, err := json.Marshal(map[string]any{"model": o.model, "keep_alive": -1})

keep_alive: -1 tells Ollama to never unload the model from memory — the delay only ever happens once, at startup.

💡
Why Local, Why Recorded

A cloud embedding API can return slightly different numbers for the exact same text on two different calls — harmless for a search bar, poison for a system that must replay byte-identical history. promptworld runs all-minilm locally through Ollama and records the vector once, so replay never recomputes it — it only rereads it.

What Matters Right Now

A villager can hold thousands of memories, but only ten fit in her head at once. Here's how she decides which ten.

Packing the Daypack

Imagine packing a small daypack before setting out — you can't carry the whole closet. You pack what matters most, weighted by how fresh it still feels, and matched to where you're actually headed.

A villager's memory window works the same way. Every planning moment, promptworld scores her whole memory shelf and packs only the top ten.

🎯

Weight by Importance

Every memory carries a salience rating — how big a deal it felt at the time.

⏳

Fade with Age

That importance isn't permanent. It quietly halves every game-day that passes — a forecast going stale.

🧭

Match the Trip

Does this memory sit close to a fresh snapshot of right now? Rope matters at a river crossing; sunscreen doesn't.

Add the first two together, throw in two wildcard memories drawn at random from the oldest half of her shelf, and that's her ten-item daypack. This "importance plus relevance" recipe is the same one behind the famous Generative Agents paper — the go-to reference whenever someone says an AI assistant "forgets what matters."

relevance01 — The Cosine Check

This is the whole function that turned each card's "relevance to right now" bar into a number, using the cosine similarity between a memory's coordinates and the situation vector's.

CODE 

func relevance01(m Memory, query []float32, queryModel string) float64 {
	if len(m.Vec) == 0 || m.VecModel != queryModel || len(m.Vec) != len(query) {
		return 0.5
	}
	var dot, mm, qq float64
	for i := range query {
		mv, qv := float64(m.Vec[i]), float64(query[i])
		dot += mv * qv
		mm += mv * mv
		qq += qv * qv
	}
	if mm == 0 || qq == 0 {
		return 0.5
	}
	return (dot/(math.Sqrt(mm)*math.Sqrt(qq)) + 1) / 2
}
PLAIN ENGLISH

relevance01 takes one memory, the situation vector to compare it against, and which model made that vector — and returns a single number.

First, bail out to a neutral score if any of three things are true...

...this memory never got a vector, or a different model embedded it, or the two vectors don't even have the same number of dimensions — return dead-center 0.5.

End of that safety check — no data, no comparison, no opinion.

Set up three running totals: the dot product, and each vector's own squared length.

Walk through every one of the situation vector's numbers, position by position.

Pull out this memory's number and the situation's number at that same position.

Add their product into the dot-product total — the heart of cosine similarity.

Add the memory's own number, squared, into its running length total.

Add the situation's own number, squared, into its running length total.

End of walking through every dimension.

One more safety check: if either vector somehow has zero length...

...there's nothing to divide by, so return the same neutral 0.5.

End of that check.

The real formula: divide the dot product by the product of both lengths — plain cosine similarity, from -1 to 1 — then squeeze it into 0 to 1 so it adds cleanly to importance.

End of relevance01.

💡
Relevance Whispers, Trauma Shouts

That squeeze into 0–1 caps relevance's contribution at +0.5. It can lift a modest memory past rivals up to five salience points stronger — enough to save a decayed-to-nothing memory like the river robbery — but it can never outshout a genuinely fresh, high-salience event.

Three Rules That Keep the Score Honest

🗺️
Neutral means no data, not "no chance"

A memory with no vector, or one embedded by a different model, scores exactly 0.5 — never punished, never promoted. Different embedding models make different coordinate charts; comparing across them would be meaningless, so relevance01 refuses to try.

🔒
Her own shelf only

The scorer's only input is that one villager's own memories. Two villagers who lived through the exact same events cannot influence each other's window — proven by a test that checks exactly this.

🎲
Even the dice are deterministic

The two wildcard slots use seeded random draws from the oldest half of her shelf, same as every other roll in the village. Replay the same history and the same memories get drawn as wildcards, every time.

🔐
Why Recency Counts From Creation, Never From Recall

The famous reference design decays memories from their last access — recalling one keeps it fresh. promptworld deliberately rejected that: a pure read must never change the data it reads, or replay stops matching the original run. Age is counted strictly from when a memory was created.

05

Trust, But Verify

The new memory score is built, tested, and fast — and not allowed to touch a single villager's mind until the evidence says it's ready.

The Understudy Who Never Steps on Stage

Every night, an understudy performs the entire play in the wings — full costume, full effort, every line delivered in step with the lead. The audience never sees her. The director watches both performances and compares notes, night after night.

promptworld's new three-term memory score is built, tested, and fast. And it is not allowed to influence a single villager's thoughts — yet.

💡
That's Not Caution Theater

That's the feature. The switch that controls this is a feature flag living in one line of config, and flipping it is deliberately the very last step, not the first.

The Dial: Three Positions, Three Behaviors

The flag lives in the world's config file, world.json, under one key: memory_relevance. It has exactly three legal values, and each one is a completely different level of trust.

🔒

"" — off

Serve the old memory window. No new scoring runs at all. This is where every villager starts.

🎭

"shadow"

Serve the old window, exactly as before — but also quietly compute the new score, every single tick, and record where the two disagree.

✅

"on"

Serve the new score for real. And keep recording anyway — the understudy never actually stops taking notes.

🚧
No Silent Typos Allowed

Type "shaddow" into that field and promptworld refuses to start the world at all. Either the value is exactly right, or nothing runs — it can never silently fall back to "off" without anyone noticing.

One Word Decides Everything

That flag isn't just documentation — it's a literal string threaded down into the function that picks a villager's memory window every time she stops to think.

CODE 

func selectWindow(s *sim.State, idx, k int, tick int64, mode string) []sim.Memory {
	a := &s.Agents[idx]
	if mode == world.MemoryRelevanceOn {
		var query []float32
		if len(a.SitVec) > 0 {
			query = a.SitVec
		}
		return sim.SelectMemoriesRelevant(a, s.Seed, idx, tick, k, query, a.SitVecModel)
	}
	return sim.SelectMemories(a, s.Seed, idx, tick, k)
}

Proven, Not Promised

A test deliberately builds a world where the old and new rankings provably differ, sets the mode to "shadow", then asserts every prompt sent to the villager's mind is byte-for-byte identical to mode "". Shadow mode can compute anything it wants; it is structurally forbidden from changing what a villager actually sees.

What Gets Recorded

So if shadow mode changes nothing a villager sees, where does all that comparing actually go? Every planning moment, in "shadow" or "on", emits one durable cog.memory_divergence event — telemetry about the comparison, not a guess about it.

CODE 

MemoryDivergencePayload struct {
	Agent        int     `json:"agent"`
	Tick         int64   `json:"tick"`
	Mode         string  `json:"mode"`
	Legacy       []int64 `json:"legacy"`
	Augmented    []int64 `json:"augmented"`
	Overlap      int     `json:"overlap"`
	Displacement int     `json:"displacement"`
	Vectorless   int     `json:"vectorless"`
	SitTick      int64   `json:"sit_tick"`
}
PLAIN ENGLISH

The shape of one disagreement record — what gets written to the event log every time both rankings are computed for a villager.

Agent: which villager this comparison is about, by ID.

Tick: the exact simulated moment this comparison happened.

Mode: what the flag was actually set to when this was recorded — "shadow" or "on".

Legacy: the top-10 memory IDs the OLD selector would have chosen.

Augmented: the top-10 memory IDs the NEW three-term scorer chose instead.

Overlap: how many IDs show up in both lists — where the two selectors actually agree.

Displacement: how far the memories they DO agree on moved rank between the old list and the new one.

Vectorless: how many candidate memories had no coordinates yet, so the new scorer couldn't judge their relevance at all.

SitTick: which situation-vector snapshot of "right now" this comparison used as its yardstick.

End of the payload. Ten numbers and two lists — durable, replayable evidence, not a printed guess.

Reading the Evidence

An operator doesn't have to comb the event log by hand. One CLI command, promptworld divergence <world>, summarizes every villager's divergence into per-game-day averages.

$ promptworld divergence riverdale villager day overlap@10 displacement vectorless elowen 1 1.00 0.0 2 elowen 2 1.00 0.0 1 tobar 1 1.00 0.0 3 tobar 2 1.00 0.0 0

Overlap 1.00 everywhere — a young world, where every memory still fits inside the window whole. There's nothing yet for the two rankings to disagree about.

📊
Real Numbers From This Feature's Own Validation Run

At max simulation speed, embedding every memory added roughly 5–6% to wall-clock time, against a 10% budget. A live shadow hour showed overlap sitting at exactly 1.00 — the villagers were still young, so the rankings couldn't disagree yet. Evidence takes time. That's the point.

The go/no-go decision — with these exact numbers attached — gets recorded on the project board before anyone flips the dial to "on". And even once it's "on", the divergence keeps recording: the director never stops taking notes, even after opening night.

What You Can Now Say to an AI Assistant

Zoom all the way out: an event happens, becomes a memory, gets coordinates, fills a window, runs in shadow, and — one day, once the evidence says so — goes live. Every step of that is recorded, and every step is replayable. The village never forgets, and it never lies about what it remembered.

event sourcing "Store every change as an event, and rebuild current state by replaying them" — instead of just overwriting a database row.
embeddings "Give this text a vector so I can compare it by meaning, not just matching words."
recency / importance / relevance "Rank memories with all three — not just whatever was said most recently."
shadow mode "Run the new logic alongside the old one and record how much they disagree, before switching over."
feature flag "Put this behind a flag so we can turn it on and off without a new deploy."
