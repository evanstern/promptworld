Trust, But Verify

The new memory score is built, tested, and fast — and not allowed to touch a single villager's mind until the evidence says it's ready.

The Understudy Who Never Steps on Stage

Every night, an understudy performs the entire play in the wings — full costume, full effort, every line delivered in step with the lead. The audience never sees her. The director watches both performances and compares notes, night after night.

promptworld's new three-term memory score is built, tested, and fast. And it is not allowed to influence a single villager's thoughts — yet.

💡
That's Not Caution Theater

That's the feature. The switch that controls this is a feature flag living in one line of config, and flipping it is deliberately the very last step, not the first.

The Dial: Three Positions, Three Behaviors

The flag lives in the world's config file, world.json, under one key: memory_relevance. It has exactly three legal values, and each one is a completely different level of trust.

🔒

"" — off

Serve the old memory window. No new scoring runs at all. This is where every villager starts.

🎭

"shadow"

Serve the old window, exactly as before — but also quietly compute the new score, every single tick, and record where the two disagree.

✅

"on"

Serve the new score for real. And keep recording anyway — the understudy never actually stops taking notes.

🚧
No Silent Typos Allowed

Type "shaddow" into that field and promptworld refuses to start the world at all. Either the value is exactly right, or nothing runs — it can never silently fall back to "off" without anyone noticing.

One Word Decides Everything

That flag isn't just documentation — it's a literal string threaded down into the function that picks a villager's memory window every time she stops to think.

CODE 

func selectWindow(s *sim.State, idx, k int, tick int64, mode string) []sim.Memory {
	a := &s.Agents[idx]
	if mode == world.MemoryRelevanceOn {
		var query []float32
		if len(a.SitVec) > 0 {
			query = a.SitVec
		}
		return sim.SelectMemoriesRelevant(a, s.Seed, idx, tick, k, query, a.SitVecModel)
	}
	return sim.SelectMemories(a, s.Seed, idx, tick, k)
}
PLAIN ENGLISH

selectWindow decides which memory window one villager sees this tick, given the world, which villager, how many memories fit, the current tick, and the mode string.

Grab that villager's own record — nobody else's memories are in play.

If the mode is exactly "on" — the only value that's allowed to change what actually gets served...

...start building a query: the coordinates of "right now", empty until filled in.

If this villager already has a situation-vector snapshot on file...

...use it as the query.

End of that check — with or without a real snapshot, move on regardless.

Run the new three-term scorer with that query and return its top picks.

End of the "on" branch.

Any other mode — including "shadow" — falls straight back to the exact same call as always. Shadow mode never reaches the branch above.

End of selectWindow.

🔬
Proven, Not Promised

A test deliberately builds a world where the old and new rankings provably differ, sets the mode to "shadow", then asserts every prompt sent to the villager's mind is byte-for-byte identical to mode "". Shadow mode can compute anything it wants; it is structurally forbidden from changing what a villager actually sees.

What Gets Recorded

So if shadow mode changes nothing a villager sees, where does all that comparing actually go? Every planning moment, in "shadow" or "on", emits one durable cog.memory_divergence event — telemetry about the comparison, not a guess about it.

CODE 

MemoryDivergencePayload struct {
	Agent        int     `json:"agent"`
	Tick         int64   `json:"tick"`
	Mode         string  `json:"mode"`
	Legacy       []int64 `json:"legacy"`
	Augmented    []int64 `json:"augmented"`
	Overlap      int     `json:"overlap"`
	Displacement int     `json:"displacement"`
	Vectorless   int     `json:"vectorless"`
	SitTick      int64   `json:"sit_tick"`
}
PLAIN ENGLISH

The shape of one disagreement record — what gets written to the event log every time both rankings are computed for a villager.

Agent: which villager this comparison is about, by ID.

Tick: the exact simulated moment this comparison happened.

Mode: what the flag was actually set to when this was recorded — "shadow" or "on".

Legacy: the top-10 memory IDs the OLD selector would have chosen.

Augmented: the top-10 memory IDs the NEW three-term scorer chose instead.

Overlap: how many IDs show up in both lists — where the two selectors actually agree.

Displacement: how far the memories they DO agree on moved rank between the old list and the new one.

Vectorless: how many candidate memories had no coordinates yet, so the new scorer couldn't judge their relevance at all.

SitTick: which situation-vector snapshot of "right now" this comparison used as its yardstick.

End of the payload. Ten numbers and two lists — durable, replayable evidence, not a printed guess.

Reading the Evidence

An operator doesn't have to comb the event log by hand. One CLI command, promptworld divergence <world>, summarizes every villager's divergence into per-game-day averages.

$ promptworld divergence riverdale villager day overlap@10 displacement vectorless elowen 1 1.00 0.0 2 elowen 2 1.00 0.0 1 tobar 1 1.00 0.0 3 tobar 2 1.00 0.0 0

Overlap 1.00 everywhere — a young world, where every memory still fits inside the window whole. There's nothing yet for the two rankings to disagree about.

📊
Real Numbers From This Feature's Own Validation Run

At max simulation speed, embedding every memory added roughly 5–6% to wall-clock time, against a 10% budget. A live shadow hour showed overlap sitting at exactly 1.00 — the villagers were still young, so the rankings couldn't disagree yet. Evidence takes time. That's the point.

The go/no-go decision — with these exact numbers attached — gets recorded on the project board before anyone flips the dial to "on". And even once it's "on", the divergence keeps recording: the director never stops taking notes, even after opening night.

What You Can Now Say to an AI Assistant

Zoom all the way out: an event happens, becomes a memory, gets coordinates, fills a window, runs in shadow, and — one day, once the evidence says so — goes live. Every step of that is recorded, and every step is replayable. The village never forgets, and it never lies about what it remembered.

event sourcing "Store every change as an event, and rebuild current state by replaying them" — instead of just overwriting a database row.
embeddings "Give this text a vector so I can compare it by meaning, not just matching words."
recency / importance / relevance "Rank memories with all three — not just whatever was said most recently."
shadow mode "Run the new logic alongside the old one and record how much they disagree, before switching over."
feature flag "Put this behind a flag so we can turn it on and off without a new deploy."
