The Clockwork Heart

Why replay never lies

Kill it. Restart it. Nothing changes.

Picture a player piano. The paper roll has holes punched in it, and any piano that loads that roll plays back the identical performance — same notes, same timing, forever. The pianist who punched the roll doesn't need to be in the room anymore.

You can stop the promptworld daemon mid-tick, delete every scrap of its running memory, and restart it cold. The village comes back byte-for-byte identical, every villager in the exact spot, every memory intact.

How is that possible? This module is the answer — and it's the same trick behind one of the most valuable patterns you can ask an AI coding assistant to build for you.

The one law

The sim runs on a single rule: state only ever changes by applying recorded events, in order. Three mechanisms make that rule unbreakable.

📜

The append-only ledger

Every world is a SQLite file with an append-only event log. Deleting a row is impossible by design — a database trigger forbids it, and every sequence number is checked for gaps.

⚙️

The reducer

One function — the reducer — is the ONLY way state changes. The exact same function runs live and during replay: load the newest verified snapshot, then re-apply.

🎲

Deterministic dice

Even randomness is deterministic: every random draw comes from the world's seed, a purpose, and the current tick. Replay rolls the exact same dice.

💡
Key insight

This is event sourcing — one of the most powerful patterns you can ask an AI assistant for. If your own app's data ever gets corrupted, or you've wished you could rewind and see exactly what happened, this is the pattern to name.

Two doors, and nothing else

The AI mind — the part that decides what a villager wants — runs entirely outside this clockwork. Its output can only enter as a recorded event, and only through two guarded doors.

🧠

The Mind — outside

The AI reasoning about villagers. It has opinions. It has no direct wires into the clockwork.

↓
🚪

Intent door

What a villager decides to do next.

🚪

Social door

A whitelisted set of event types. Nothing else gets in.

↓
⚙️

The Clockwork — inside

The deterministic sim. Nothing enters except through a door.

Arrows point only inward. There is no door that lets the Clockwork reach back out to the Mind.

Even a "thought" has to mail itself in

Spec 042 added three new entries to the social door's whitelist. Even the AI's own understanding of a memory — its embedding vector — has to enter as a recorded payload, never computed live inside the Clockwork.

internal/sim/loop.go — excerpt (three of the whitelist's entries; the real map has more)

CODE 

var injectSocialWhitelist = map[string]bool{
	"agent.memory_embedded":    true,
	"agent.situation_embedded": true,
	"cog.memory_divergence":    true,
}
PLAIN ENGLISH

Start a list of every event type the social door will let through.

Yes: a recorded memory embedding is allowed in.

Yes: a recorded situation embedding is allowed in too.

Yes: a note that the AI's memory of something has diverged from the record is allowed in.

That's the whole list. Anything not on it gets rejected automatically.

Once that event is recorded, the reducer is what actually applies it — and it does exactly what the log says, nothing more.
